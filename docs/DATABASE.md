# Database Design

## Overview

MongoDB is used with Mongoose ODM. Collections map to domain entities with clear ownership and role-based access enforced in the API layer.

## Collections

### users
| Field | Type | Notes |
|-------|------|-------|
| name | String | required |
| email | String | unique, indexed |
| password | String | bcrypt hashed, excluded by default |
| role | String | `user` \| `admin` |
| timestamps | Date | createdAt, updatedAt |

### tickets
| Field | Type | Notes |
|-------|------|-------|
| title | String | required |
| description | String | required |
| category | String | technical, billing, general, account, feature |
| priority | String | low, medium, high, urgent |
| status | String | open, in_progress, resolved, closed |
| createdBy | ObjectId → users | ticket owner |
| assignedTo | ObjectId → users | optional admin assignee |
| timestamps | Date | |

**Indexes:** `{ createdBy, status }`, `{ status, priority }`, text index on title + description.

### comments
| Field | Type | Notes |
|-------|------|-------|
| ticket | ObjectId → tickets | indexed |
| author | ObjectId → users | |
| body | String | required |
| timestamps | Date | |

### activitylogs
Stores event-driven audit entries (`TICKET_CREATED`, `TICKET_UPDATED`, `STATUS_CHANGED`, `COMMENT_ADDED`, `TICKET_RESOLVED`) with actor, ticket reference, message, and metadata.

### notifications
Per-user inbox entries generated by event handlers (status changes, comments, new tickets for admins).

## Relationships

```
User 1──* Ticket (createdBy)
User 1──* Ticket (assignedTo, optional)
Ticket 1──* Comment
User 1──* Comment (author)
Ticket 1──* ActivityLog
User 1──* Notification
```

## Access rules (enforced in controllers)

- Users can CRUD only their own tickets (delete limited to `open` status).
- Users can comment only on tickets they own.
- Admins can list/filter all tickets, update status/priority, comment on any ticket, and view activity logs.
